Multi-tenant SaaS

FlowHR isolates each company tenant. These rules apply to the web app, API, and Postman testing.

Session & JWT

  • Access token lifetime: 8 hours (480 minutes).
  • Browser session uses HttpOnly cookie flowhr_access_token (not readable by JavaScript).
  • Password reset link: 24 hours default.
  • Invitation link: 24 hours default.
  • After permission or tenant module changes, users must re-login.

Tenant isolation

  • Every tenant API call must include X-Tenant-ID matching the logged-in user's tenant.
  • JWT tenantId and header must match — otherwise request is rejected.
  • Database queries are scoped per tenant (Prisma extension + service checks).
  • Cross-tenant reports are SUPER_ADMIN only.

Rate limits (public/auth endpoints)

  • Login: 10 attempts / 15 min per IP
  • Password reset & signup: 5 / 15 min per IP
  • Invitation resolve/accept: 20 / 10 per 15 min per IP

Postman / API testing

  1. POST /api/auth/login with email, password, companyCode
  2. Copy accessToken and user.tenantId from response
  3. Add headers: Authorization: Bearer <token> and X-Tenant-ID: <tenantId>
  4. Wrong tenant header → 401. Missing role → 403.

Company Admin checklist

  • Assign module roles only on Users & Permissions — least privilege.
  • Do not share login credentials between employees.
  • Offboard users promptly (employee offboard disables access).
  • Use email invite so employees set their own password.
